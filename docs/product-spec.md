# 製品仕様

## 目的

Nousarium は、対話を知識へ変換し続ける個人用ナレッジ OS です。チャットそのものが目的ではなく、思想・技術・プロジェクトを一つの Obsidian Vault に育てることが目的です。

## 利用者

- 単一ユーザー
- Tailscale の tailnet 内からのみアクセス
- 到達制御は Tailscale。アプリは Bearer トークンで agent-service と通信する

## 中心フロー

1. スマホまたは PC で会話を開始する
2. 開始時に会話モードとアクセス権限を選ぶ
3. 必要なら途中でモードと権限を変更する（次の送信から適用）
4. AI が Vault を参照し、要点・疑問・決定を整理する
5. 新規ノート案を提示する
6. 保存先・タイトル・本文を確認して Vault に保存する
7. 書き込みは Git に記録され、差分と復元ができる

## 会話モード

| 値 | 意味 |
| --- | --- |
| `plan` | 調査・検討・提案。実装より整理を優先する |
| `agent` | 許可された範囲で実際の作業を行う |

Cursor Agent の会話モードに対応します。会話の途中で切り替え可能です。

## アクセス権限

| 値 | できること |
| --- | --- |
| `chat` | テキスト応答。Vault には触れない |
| `read` | Vault の読み取りと検索 |
| `vault-work` | 隔離された Vault 内での作成・編集・移動・Shell |

権限は Run 開始時に固定します。実行中の昇格はしません。変更は次の送信から適用します。実行中に変更した場合は「次回から適用」と表示します。

`vault-work` では `rg` などの Shell を許可します。範囲は Vault ディレクトリ内に限定します。ホスト全体、システムリポジトリ、runtime、秘密情報には到達しません。

## ノート

主な作業は新規ノート作成です。既存ノートの大幅な書き換えより、対話からの抽出・Inbox 投入・Knowledge への昇格を優先します。

保存時に確認する項目:

- 保存先ディレクトリ
- タイトル（日本語）
- YAML Properties
- 本文
- 既存ファイルとの差分（上書き時）

## 対話ログ

会話の全文は Vault の `10_Journal/Conversations/` に Markdown として永久保存します。runtime の SQLite は会話一覧、Agent ID、権限スナップショット、Run 状態のための作業用索引です。

| 操作 | 挙動 |
| --- | --- |
| 通常の検索除外 | `ai_access: excluded`。AI の文脈構築から外す |
| 保護領域 | Agent が読めないディレクトリへ移す |
| 通常削除 | `Trash/` へ移動。Git から復元できる |
| 手動完全削除 | 明示確認が必要 |

## 同時編集

Web エディター、Obsidian、AI が同じファイルを触る場合があります。保存時に読み込み時ハッシュと現在ハッシュを比較し、不一致なら上書きせず差分確認へ進みます。書き込み Run は Vault 単位で同時に 1 件です。

## 対象外

- 複数ユーザー
- インターネットへの直接公開
- 音声入力
- 意味検索
- 共同編集 CRDT
- 完全 WYSIWYG
- Vault の自動リモート作成
- 完全削除の履歴抹消

## 受入条件

- 公開システム Repo に個人データが入らない
- 新規非公開 Vault を初期化できる
- スマホから会話し、途中でモード・権限を変更できる
- Vault を検索し、新規 Markdown ノートを作成できる
- 競合時に黙って上書きされない
- 書き込み Run を Git から確認・復元できる
- Cursor SDK、Markdown Editor、Vault 実装を Port 単位で交換できる
