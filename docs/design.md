# UI 設計

値の正本は [packages/ui/src/styles.css](../packages/ui/src/styles.css) の `@theme` と、そこに続くテーマ上書きです。この文書は意味と使い方を定めます。

## 原則

- 長文を読み書きする道具として設計する。装飾よりも可読性と静けさを優先する
- モバイルファースト。片手で送信、Vault 更新の切り替え、差分確認ができる
- チャットを主画面にし、ノート編集と差分は必要なときだけ前面に出す
- 状態（生成中、失敗、競合、復元可能）を色と文言の両方で区別する
- 画面ごとに配色を変えない。1 つのトークン体系で全画面を組む

## テーマ

ライトとダークを用意します。既定は OS 設定への追従です。

### 仕組み

セマンティックトークンだけを使い、テーマの差は**変数の値**だけで表します。コンポーネントに `dark:` 修飾子を書きません。`bg-surface` は両テーマで正しい背景になります。

```css
@theme {
  --color-surface: #f4f1ea;
  /* ライトの値 */
}

:root[data-theme="dark"] {
  --color-surface: #171612;
  /* ダークの値で上書き */
}
```

Tailwind v4 のユーティリティは `var(--color-surface)` を参照するため、変数を上書きするだけで全ユーティリティが追従します。この規約を破って `dark:bg-*` を書くと、テーマが 2 か所に分散して必ず食い違います。

### 切り替え

`<html>` の `data-theme` 属性で決めます。値は `light` `dark` の 2 つ。属性が無いときは OS 設定に従います。

| 設定 | `data-theme` | 解決 |
| --- | --- | --- |
| システム（既定） | 属性なし | `prefers-color-scheme` |
| ライト | `light` | 固定 |
| ダーク | `dark` | 固定 |

要件:

- 選択は `localStorage` に保存する
- 描画前に同期スクリプトで属性を当て、初回のちらつきを防ぐ
- `color-scheme: light dark` を `:root` に置き、スクロールバーとネイティブフォーム部品を追従させる
- `<meta name="theme-color">` を `prefers-color-scheme` 付きで 2 つ出し、PWA のステータスバーを合わせる
- 切り替え UI はノート画面の設定ではなく、アプリバーのオーバーフローメニューに置く

### コントラスト

- 本文と背景は 7:1 以上
- 補助文、境界に接する文字は 4.5:1 以上
- アイコンと図形のみの要素は 3:1 以上
- 塗りボタンの文字色はトークンで持たず、`accent` の上は常に白（ダークでは `surface`）を使う

## タイポグラフィ

| 役割 | サイズ | 行間 | 用途 |
| --- | --- | --- | --- |
| `display` | 30px | 1.3 | 新規対話の問いかけ |
| `title` | 20px | 1.4 | 画面見出し、会話タイトル |
| `heading` | 16px | 1.5 | セクション見出し |
| `body` | 16px | 1.75 | 本文、チャット、Markdown |
| `ui` | 14px | 1.5 | ボタン、ラベル、リスト |
| `caption` | 12px | 1.4 | 時刻、件数、パス |
| `mono` | 13px | 1.6 | diff、コード、Frontmatter |

日本語の長文が主なので、本文の行間を広く取ります。

- 入力欄の文字は 16px、行間は 1.5。本文トークンの 1.75 は使わない。iOS で focus 時に画面が拡大するのを防ぐ
- 本文に `font-feature-settings: "palt"` を当て、約物の空きを詰める
- `line-break: strict` と `overflow-wrap: anywhere` を本文に当てる
- 見出しと本文に `text-wrap: pretty` を当て、末尾の孤立文字を避ける
- 読み幅は本文 42rem、チャット 46rem を上限にする

## 余白・角丸・境界・影

余白は Tailwind の既定スケール（0.25rem 単位）をそのまま使い、レイアウトの刻みを `2` `3` `4` `6` `8`（8/12/16/24/32px）に寄せます。独自のスペーシング変数を作りません。

| 対象 | 角丸 |
| --- | --- |
| ボタン、入力、リスト行 | `rounded-lg`（8px） |
| カード、パネル、diff | `rounded-xl`（12px） |
| シート、モーダル、吹き出し | `rounded-2xl`（16px） |
| ピル、アバター | `rounded-full` |

境界と影の使い分け:

- 面の区切りは原則 `border-stroke` の 1px で表す
- 影はライトで浮いている要素（ポップオーバー、シート、トースト）にのみ使う
- ダークでは影が読めないため、`surface-elevated` の明度差で階層を表す。影に頼らない

## レイアウト

### ブレークポイント

| 名前 | 幅 | 構成 |
| --- | --- | --- |
| モバイル | `< 768px` | 1 カラム + 下部タブ |
| タブレット | `768px 〜 1023px` | サイドバー + 主領域 |
| デスクトップ | `>= 1024px` | サイドバー + 主領域 + コンテキスト |

### 領域

```text
デスクトップ
┌──────────┬─────────────────────────┬──────────────┐
│ サイドバー │ アプリバー                │ コンテキスト   │
│ 260px    ├─────────────────────────┤ 360px        │
│ 対話:会話  │ 本文（読み幅 46rem 中央）  │ 差分 / プレビュー │
│ ノート:タグ ├─────────────────────────┤ 折りたたみ可   │
│          │ 入力                      │              │
└──────────┴─────────────────────────┴──────────────┘

モバイル
┌─────────────────────────┐
│ アプリバー                │  ← 1 段だけ
├─────────────────────────┤
│ 本文                     │
│                          │
├─────────────────────────┤
│ 入力（safe-area 込みで固定）│
├─────────────────────────┤
│ 対話 │ ノート │ 変更       │  ← 下部タブ
└─────────────────────────┘
```

縦に積むバーは常に 1 段までにします。サイドバーの中身は画面で切り替わります。対話では会話リスト、ノートでは階層タグのフォルダツリーです。モバイルではアプリバー左のアイコンから開くスライドオーバーで出します。

コンテキスト領域は、Run に差分があるとき、またはノートを開いたときだけ開きます。既定は閉じた状態です。

### アプリバー

1 段に収めます。

- 左: アプリアイコン。閉じているときはここからサイドバーを開く。開いているときは同じ画面位置でサイドバー先頭に移り、アプリ名と閉じる操作を同じボタンにまとめる。開いているときは開くボタンは置かない
- 中央: 現在地（会話タイトル、フォルダ名、または画面名）。1 行で省略する
- 右: オーバーフローメニュー（モデル、テーマ、この対話を隠す）

頻繁に変えない設定はメニューに畳みます。バーに並べません。

### ナビゲーション

- モバイル: 下部タブ 3 つ（対話 / ノート / 変更）。タップ領域 56px、safe-area を加算する
- タブレット以上: サイドバー下部に同じ 3 つを縦に置く
- 現在地はアイコンの塗りと文字色の両方で示す
- `Ctrl+Shift+O` でどの画面からでも新しい対話を開く

## 画面

### チャット

役割ごとに見せ方を変えます。

- 自分: 右寄せの塗り吹き出し。`accent-soft` の地、最大幅 80%、`rounded-2xl`
- AI: 全幅のプレーンテキスト。枠を付けない。左に 2px の `accent` レールを添え、上下の余白で区切る

AI の応答は長文になるため、枠で囲まず読み幅いっぱいに流します。枠は視線の妨げになります。

- 送信から最初の本文まで、いまの段階を 1 行で出す（送信、会話名、記録、準備、思考、ツール）。ストリーム中は本文を逐次追加し、末尾にキャレットを表示する
- 応答中に利用者がスクロールしたら自動追従を止める。次の送信で再開する
- ツール実行は 1 行に畳んで表示し、連続するものはまとめる。詳細は展開で見せる
- 停止ボタンは生成中のみ、送信ボタンと同じ位置に出す
- 失敗時は原因と再送を同じ吹き出しの下に置く
- 参照したノートは `[[Wikilink]]` としてタップでき、コンテキスト領域にプレビューを出す
- ノートの更新は要約 1 行（何ファイル、何行）を先に出し、詳細はコンテキスト領域で見せる
- 対話ログの差分は既定で畳み、ノートの変更を先に見せる

### 入力

- 入力欄は内容に応じて縦に伸びる。上限 8 行、超えたら内部スクロール
- 左に Vault 更新のトグルを置く。送信の直前に見える位置に常時出す
- 右に送信（生成中は停止）
- モバイルではキーボード表示時も入力欄と送信が隠れないよう、`env(safe-area-inset-bottom)` を加えて固定する
- `Enter` で送信、`Shift+Enter` で改行

新規対話の初期画面は、問いかけの見出しと入力欄だけにします。モデルはオーバーフローメニュー、Vault 更新は入力欄左のトグルで足ります。

### ノート

ファイルは `Notes/` にフラットに置きます。画面上のフォルダは階層タグ（`思考/内省`）から作る仮想フォルダです。1 ノートが複数のタグを持てば、複数のフォルダに現れます。タグのないノートは「未分類」です。

```text
┌──────────────┬──────────────────────┐
│ 検索           │ フォルダ名               │
│ すべて         │ ──────────────────── │
│ 思考           │ ノート一覧 または         │
│   内省         │ パス + Properties     │
│     ノート     │ 編集 | プレビュー         │
│ 未分類         │                        │
└──────────────┴──────────────────────┘
```

- サイドバーにタグ階層をフォルダツリーとして出す。シェブロンで開閉し、名前でそのフォルダを選ぶ。第1段は最初から開く
- 「すべて」は全ノート、「未分類」はタグのないノート。件数を行の右に出す
- 展開したフォルダの直下に、そのタグを持つノートを並べる
- 検索はツリーを絞り、本文ヒットもサイドバーに出す
- 主領域は選択中フォルダのノート一覧。タイトルを主、タグと更新日を副にする
- タグのピルをタップすると、そのタグのフォルダを開く
- ノートを開くと主領域は編集画面になる。2ペイン（原文とプレビューを左右）と 1ペイン（タブ切替）を手動で切り替える。未選択時は広い画面では 2ペイン、狭い画面では 1ペイン。選択は端末に残す。プレビューは編集中の内容を描画する。WYSIWYG にはしない
- Frontmatter は折りたたみ可能な Properties 領域として、表形式で見せる
- Properties の下に「関連する対話」を置く。更新した対話と参照した対話を分け、`/c/{id}` へリンクする
- 「このノートについて話す」で `/?note=<path>` へ行き、入力欄に `[[ノート名]]` を入れる
- 保存はトーストで知らせる。画面内に固定の成功文を残さない
- 場所は URL で持つ。`/files?tag=思考/内省`、`/files?untagged=1`、`path` で開いているノート
- モバイルではフォルダツリーをシートで出し、一覧と本文を 2 画面に分ける

### 変更履歴

- Run を時刻の降順で並べ、各行に状態・時刻・変更ファイル数を出す
- 選択すると右に差分と復元を出す
- モバイルでは一覧と詳細を 2 画面に分ける

## コンポーネント

`packages/ui` に置く粒度です。

| 名前 | 用途 |
| --- | --- |
| `Button` | `primary` `secondary` `ghost` `danger`。高さ 44px |
| `IconButton` | アプリバー、入力欄。44px 正方形。幅いっぱいに伸ばすときは `layout="bar"` |
| `BarButton` | 先頭アイコン・ラベル・末尾アイコンを 1 つの操作にまとめる。サイドバー先頭の閉じる操作 |
| `Pill` | 状態、タグ、件数。`accent` `warning` `danger` `success` `neutral` |
| `Field` | ラベルと入力の組。説明文とエラーを持てる |
| `TextInput` / `Textarea` / `Select` | 素の要素セレクタではなく、コンポーネントで統一する |
| `Switch` | Vault 更新のトグル |
| `Sheet` | モバイルの会話リスト / タグフォルダ、コンテキスト |
| `Menu` | オーバーフローメニュー |
| `Toast` | 保存完了、復元完了 |
| `EmptyState` | 一覧が空のときの案内 |
| `Skeleton` | 読み込み中の骨組み |

素の `input` `textarea` `select` に対するグローバルなスタイル指定は置きません。要素セレクタで当てるとユーティリティと競合し、変種が作れなくなります。

## 差分と競合

- 追加は `success` の文字色と `success-soft` の地、削除は `danger` と `danger-soft`
- 色だけに頼らず、行頭の `+` `-` を残す
- ファイルごとに `+n / -n` を出す
- Run 単位の要約（何ファイル、何行）を先に見せ、詳細 diff は展開する
- 競合時は「自分 / ディスク」を並べ、採用操作を明示する
- 破壊的な復元はボタン文言を「この変更を取り消す」にする

## Markdown 表示

- 見出しは 3 段まで視覚的に区別する。4 段以降は太字扱い
- 段落間は 1 行分空ける。行間は本文トークンに従う
- コードブロックは `surface-sunken` の地、横スクロール可
- 表は横スクロール可。セルを折り返さない
- `[[Wikilink]]` は `accent` の下線付き。未作成のリンクは `text-muted` の破線にする
- タグは `accent-soft` のピル
- 引用は左 2px の `stroke-strong` と `text-secondary`

未作成の Wikilink を淡く表示することで、「そろそろ書くべき概念」が読んでいて分かります。

## アクセシビリティ

- タップ領域は 44px 以上。ツリーの開閉など隣接する操作は 32px 幅でも、行全体で 44px を確保する
- フォーカスリングは `stroke-strong` の 2px。`outline-hidden` で消さない
- ストリーム領域は `aria-live="polite"`、エラーは `aria-live="assertive"`
- 色だけに依存しない。アイコンまたは文言を添える
- `prefers-reduced-motion` を尊重し、モーションを無効化する
- キーボードで会話リスト、入力、送信、差分の展開まで到達できる
- `Ctrl+Shift+O` は入力中でも新しい対話に切り替える
- 画像とアイコンボタンに名前を付ける

## Tailwind の使い方

Tailwind v4 を CSS ファーストで使います。

- 設定は `@theme`。`tailwind.config.js` を置かない
- 色は必ずセマンティックトークンで指定する。`bg-[#fff]` や `text-stone-500` を書かない
- 変種の合成は `clsx` と `tailwind-merge` に任せ、テンプレートリテラルでのクラス結合をやめる
- 3 箇所以上で同じクラス列が出たらコンポーネントに切り出す。`@apply` で隠さない
- v4 の名称に従う（`shadow-xs` `rounded-sm` `outline-hidden` `shrink-0`、`!` は末尾）

### ライブラリ

素の Tailwind に加えて、次を採用します。

| ライブラリ | 用途 | 理由 |
| --- | --- | --- |
| `clsx` + `tailwind-merge` | クラスの合成と衝突解決 | 実行時の UI 方針を持ち込まない |
| Radix UI Primitives | `Sheet` `Menu` `Switch` `Toast` `Tooltip` | フォーカストラップ、`aria` 属性、キーボード操作を自前で書かない |

Radix は見た目を持たないため、上のトークン体系をそのまま当てられます。

shadcn/ui は採用しません。独自のトークン語彙（`--background` `--foreground` `--primary`）を持ち込み、`surface` / `text-primary` / `accent` と二重になります。必要なのは対話・シート・メニュー程度で、レジストリ全体を抱える利点がありません。

## 使わないもの

- 絵文字をアイコン代わりにする
- 強いグラデーション、装飾的な影
- 画面ごとの別配色
- Vault 更新の状態を隠したフローティング操作
- モバイルでのホバー前提の操作
- 意味を持たないアニメーション
